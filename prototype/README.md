# Prototype — MedMind

Clickable prototype (HTML / CSS / JavaScript) — **เปิดในเบราว์เซอร์ได้เลย ไม่ต้องมี server หรือฐานข้อมูล**

## วิธีเปิด

**เปิดออนไลน์:** [เว็บแอป](https://claude.ai/artifact/Tjx97w6AbSVXBH3APZ86pE) (ต้องได้รับแชร์ลิงก์ก่อน) · หรือเปิดจากไฟล์ในเครื่อง:

1. ดาวน์โหลด repo (Code → Download ZIP) แล้วแตกไฟล์
2. ดับเบิลคลิกเปิด `prototype/index.html` ด้วย Chrome / Edge / Safari
3. หน้าเว็บแสดงโทรศัพท์ 2 เครื่องคู่กัน — ซ้าย = ผู้สูงอายุ (Senior), ขวา = ผู้ดูแล (Caregiver) — ใช้ข้อมูลชุดเดียวกัน
4. แถบด้านบนเป็น **เครื่องมือ demo** (ไม่ใช่ส่วนของแอป): เลื่อนเวลาจำลอง, ไปวันถัดไป, ใช้เวลาจริงของเครื่อง, โหลดสถานการณ์ตัวอย่าง, ปิดสิทธิ์กล้อง, และบันทึกเหตุการณ์ที่เกิดขึ้น

> แตะหน้าจอ Senior 1 ครั้งก่อน เพื่อให้เบราว์เซอร์ยอมเล่นเสียงเตือน (SRS §2.2)

## ลำดับการ demo (ตาม acceptance criteria ใน SRS §3)

**เลือกบทบาท (R0)** — เปิดมาทั้งสองเครื่องอยู่ที่หน้าเลือกบทบาท: เครื่องซ้ายกด "ผู้สูงอายุ" เครื่องขวากด "ผู้ดูแล / ลูกหลาน" (ทั้งสองเครื่องเลือกได้ทั้ง 2 บทบาทเสมอ · เครื่องที่กดได้บทบาทที่เลือก ถ้าต้องสลับ โทรศัพท์จะสลับข้างให้ · ถ้าเลือกซ้ำกับอีกเครื่อง อีกเครื่องจะเปลี่ยนเป็นอีกบทบาทและกลับไปหน้าเริ่มต้น เพราะ prototype จำลอง Senior 1 คนกับ Caregiver 1 คน — BR-02) · ปุ่มสถานการณ์ในแถบ demo ข้ามหน้านี้ให้

**FR-01 จับคู่** — เริ่มจากหน้าเปล่า แล้วเลือกบทบาททั้งสองเครื่อง
1. Caregiver ใส่รหัส (หรือสแกน QR) ก่อน Senior ยินยอม → "รอผู้สูงอายุกดยินยอมก่อน" (✗2)
2. Caregiver ใส่รหัสผิด → "รหัสไม่ถูกต้องหรือหมดอายุ" (✗4) · กด +15 นาที แล้วใส่รหัสเดิม → รหัสหมดอายุ (✗4)
3. Senior กด "สร้างรหัสใหม่" + "ยินยอม" → Caregiver สแกน QR → ทั้งสองเครื่องเชื่อมต่อแล้ว (✓1, ✓3)
   - **กล้องสด:** กด "สแกน QR" → เล็งกล้องไปที่ QR บนจอ Senior (เช่น ถ่ายรูป QR บนจอด้วยมือถือ แล้วยกให้กล้องโน้ตบุ๊กเห็น) → จับคู่เองเมื่ออ่านได้ · "หยุดสแกน" ปิดกล้อง
   - **จากรูป:** แคปหน้าจอ QR ของ Senior → "เลือกรูป QR จากเครื่อง" → เลือกรูปนั้น · รูปที่ไม่มี QR ของ MedMind → "ไม่พบ QR ของ MedMind ในรูปนี้"
4. กดปุ่ม demo "Caregiver คนที่ 2 ใส่รหัส" → "ผู้สูงอายุท่านนี้มีผู้ดูแลแล้ว" (✗5)

**FR-02 เพิ่มยาจากฉลาก** — แท็บ "เพิ่มยา" ในเมนูล่าง
- กด "ถ่ายรูป / เลือกรูปฉลาก" → เลือกรูปใน `prototype/samples/` (หรือถ่ายฉลากจริงบนมือถือ) → "กำลังอ่านฉลาก…" (ครั้งแรกนานกว่า ต้องโหลดตัวอ่าน) → ได้ร่างให้ตรวจ
  - `label-after-meal.png` → ร่างครบ หลังอาหาร (✓1, ✓6) + บอกว่าฉลากระบุหลายมื้อ
  - `label-bedtime.png` → ก่อนนอน + ข้อควรระวัง (✓9)
  - `label-before-meal.png` → "ก่อนอาหาร" ไม่ระบุนาที → ช่องกรอบส้ม "กรุณาตรวจสอบ" บันทึกไม่ได้ (✗10, ✗3) → ใส่ 30 → บันทึกได้ (✓8)
  - `label-as-needed.png` → ยาเมื่อมีอาการ ไม่สร้างตาราง (✗4)
  - รูปที่ไม่มีตัวหนังสือ → อ่านฉลากไม่ได้ → ฟอร์มว่างให้กรอกเอง (✗5)
- แก้ชื่อยาในร่างแล้วบันทึก → ค่าที่บันทึกคือค่าที่แก้ (✓2) · กด "ยกเลิก" → ไม่บันทึก (✗7)

**FR-03 / FR-04 / FR-05 วงจรหลัก** — กด "มื้อ 08:00 มียา 2 ตัว" แล้วแตะหน้าจอ Senior
1. ไปที่เวลา 08:00 → หน้าเตือนแสดงยา 2 ตัว + เสียง + ปุ่ม (FR-03 ✓1) · Caregiver เห็น "กำลังเตือน"
2. กด "ยังไม่กิน" → +5 นาที → แจ้งซ้ำรอบ 2 (FR-04 ✓3, FR-03 ✗2) → +5 นาที → รอบ 3
3. กด "ยังไม่กิน" ในรอบ 3 → Caregiver ได้ "ยังไม่ยืนยันการกินยา" ทันที (FR-04 ✗4) → +5 นาที (08:15) → ไม่แจ้งซ้ำ (FR-05 ✓5)
4. ไปที่ 08:40 → หน้าแรก Senior กด "กินแล้ว" → "กินแล้ว (ยืนยันช้า) 08:40" และ Caregiver ได้ "ยืนยันการกินยาแล้ว เวลา 08:40" (FR-04 ✓5, FR-05 ✓6)
- โหลดสถานการณ์ใหม่ → ไปที่ 08:03 กด "กินแล้ว" → "กินแล้ว 08:03" (FR-04 ✓1) → กดซ้ำไม่บันทึกซ้ำ (✗2) → 08:15 ไม่แจ้ง Caregiver (FR-05 ✓1, FR-03 ✓3)
- โหลดสถานการณ์ใหม่ → ไปที่ 12:00 → มื้อ 08:00 ยืนยันไม่ได้แล้ว คง "ยังไม่ยืนยัน" (FR-04 ✗6)
- กด "มื้อซ้อน 06:45 + 07:00" → ไปที่ 07:00 → หน้าเตือนแสดง 2 มื้อแยกหัวข้อ เสียงครั้งเดียว และ Caregiver ได้แจ้งของมื้อ 06:45 (FR-03 ✗4)

**ยกเลิกการจับคู่** — แท็บ "จับคู่" หรือลิงก์ใต้หน้าแรก Senior → กล่องยืนยัน → ข้อมูลยาและประวัติถูกลบ Senior เห็น QR ใหม่ (FR-01 ✗6)
**หน้าสถานะว่าง** — จับคู่ใหม่โดยยังไม่เพิ่มยา → "ยังไม่มีมื้อยาวันนี้" (FR-05 ✗4)

## ข้อจำกัดของ prototype

- ไม่มี backend จริง: โทรศัพท์ 2 เครื่องอยู่ในหน้าเว็บเดียว ใช้ข้อมูลร่วมกันในหน่วยความจำ · รีเฟรชหน้า = เริ่มใหม่
- เวลาเป็นนาฬิกาจำลอง (เลื่อนเองหรือกดเดินอัตโนมัติ) · ยาที่บันทึกหลังเวลาเตือนของวันนี้ไปแล้ว จะเริ่มเตือนพรุ่งนี้
- สวิตช์ "ใช้เวลาจริงของเครื่อง": นาฬิกาจำลองเดินตามนาฬิกาเครื่อง (เช่น ตั้งยา 08:06 แล้วเตือนตอน 08:06 จริง) · ปุ่มเลื่อนเวลาจะกดไม่ได้ระหว่างเปิด · ถ้าวันหรือเวลาจำลองไม่ตรงกับเวลาจริง จะเริ่มวันตามเวลาจริงใหม่ (มื้อที่ผ่านไปแล้วไม่สร้างย้อนหลัง) · ไม่มี server จึงต้องเปิดหน้าเว็บค้างไว้ถึงจะเตือน
- ปุ่ม "ไปวันถัดไป" ขึ้นวันใหม่ที่เวลา 06:00: สร้างมื้อของวันนั้นจากยาที่บันทึกไว้ตามความถี่และวันเริ่ม–สิ้นสุด · สถานะมื้อและการแจ้งเตือนของวันก่อนเริ่มใหม่ (การจับคู่และยาที่บันทึกยังอยู่)
- วันที่จำลองเริ่มจากวันนี้ของเครื่อง · ยาที่ตั้งความถี่หรือวันเริ่มไว้แล้ววันนี้ไม่ตรง (เช่น เลือกเฉพาะวันอื่น หรือเริ่มพรุ่งนี้) จะไม่มีมื้อในวันนี้ และข้อความหลังบันทึกจะบอกไว้
- อ่านฉลากในเครื่องด้วย Tesseract.js (ไม่ส่งรูปออกนอกเครื่อง · ไม่เก็บรูป) · ใช้ได้ทั้งดับเบิลคลิกและลิงก์เว็บ · ครั้งแรกโหลดตัวอ่าน ~12 MB
- อ่านได้ดีกับฉลากรูปแบบโรงพยาบาล (ชื่อยาภาษาอังกฤษ + [จำนวนจ่าย], "ครั้งละ … เม็ด", "ก่อน/หลังอาหาร …") · ฉลากรูปแบบอื่นอาจได้ร่างไม่ครบ → ผู้ดูแลต้องตรวจทุกครั้ง · NFR-08 ยังไม่ได้วัดกับฉลากจริง
- ฉลากที่ระบุหลายมื้อ: ร่างใช้มื้อแรก แล้วเพิ่มยาอีกครั้งสำหรับมื้อที่เหลือ (ยา 1 รายการเตือน 1 มื้อ)
- QR เป็น QR จริง (`MEDMIND:<รหัส>`) แต่ไม่มี server: รหัสอยู่ในหน้าเว็บนี้เท่านั้น → สแกน QR จากหน้าเว็บที่เปิดบนอีกเครื่องจะได้ "รหัสไม่ถูกต้อง"
- กล้องสดต้องเปิดผ่าน https หรือดับเบิลคลิกบนคอมพิวเตอร์ (Chrome / Edge) · ถ้าใช้กล้องไม่ได้ ปุ่ม "สแกน QR" จะเปิดหน้าต่างเลือก/ถ่ายรูปแทน
- ช่อง "ไม่อนุญาตกล้อง" ในแถบ demo ซ่อนปุ่มสแกนทั้งหมด เพื่อสาธิตทางสำรอง (ใส่รหัส / กรอกยาเอง)
- ชื่อยาเป็นชื่อสมมติ ใช้สาธิตเท่านั้น
